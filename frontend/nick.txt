  Checkpoint 1 stale-heartbeat fix — done, staged for your approval

  What was wrong: presence was tracked only by role (USER/ASTROLOGER), with no
  notion of which connection sent an event. A heartbeat sent moments before a
  leave/disconnect could have its async role lookup resolve after the departure
  was already applied, silently reviving a chat that should have stayed paused.

  The fix — ConnectionIdentity (socket id + a synchronously-captured per-socket 
  sequence number):
  - backend/src/modules/chat/billing.ts: recordHeartbeat/recordDeparture now
  take an optional conn: {id, seq}. A heartbeat from the same connection with a
  seq no newer than the last applied event for it is rejected as stale. A
  departure from a connection that's been superseded by a newer one is ignored.
  A heartbeat from a different connection id always takes over (legitimate
  reconnect). Calls without conn (direct test/legacy callers) are unaffected —
  exact old behavior.
  - backend/src/realtime/socketServer.ts: added nextConn(socket), which bumps a
  per-socket counter synchronously at the instant the raw event arrives — before
  any await — so true arrival order survives even when async resolution order
  doesn't. Wired into chat:join, chat:heartbeat, chat:message, chat:leave, and
  disconnecting.
  - No schema changes, no change to settlement/authoritative billing math,
  multi-tab departure logic (reportDepartureIfLast) untouched.

  Tests added — backend/src/__tests__/financial/presenceStaleness.node-test.ts
  (6 tests, simulated clock, direct ConnectionIdentity injection to
  deterministically force the exact races):
  1. Heartbeat in flight before chat:leave lands → rejected, chat stays paused.
  2. Heartbeat racing a disconnect's departure → rejected.
  3. Legitimate reconnect (new connection id, any seq) → always restores
  presence.
  4. Duplicate leave/disconnect on the same connection → idempotent, billed
  once.
  5. Departure from a superseded (old) connection → ignored, active session
  untouched.
  6. No billing accrues after a departure until a genuinely valid heartbeat
  restores presence.

  Multi-tab and reconnect behavior over real sockets is already covered by the
  existing socketPresence.node-test.ts suite, which still passes unchanged.
